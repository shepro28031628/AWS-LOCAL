# EC2: servidores virtuales

[Volver al índice](README.md)

## Qué es y cuándo usarlo

**Amazon EC2** (*Elastic Compute Cloud*) te da **servidores virtuales** (instancias) en la nube: eliges el sistema operativo y el tamaño, entras por SSH y haces lo que quieras, como en tu propio servidor.

En AWS Nube Local cada instancia es un **contenedor Docker con Amazon Linux 2023**, al que puedes entrar por SSH.

Úsalo cuando necesites control total del sistema: instalar programas propios, servidores tradicionales, practicar administración Linux.

## Conceptos clave

| Concepto | Qué es |
|---|---|
| **Instancia** | Un servidor virtual |
| **AMI** | La imagen del sistema operativo con la que arranca |
| **Tipo de instancia** | Tamaño: `t3.micro`, `t3.large`... (en local no cambia nada) |
| **Par de claves** (*key pair*) | Clave pública (en el servidor) y privada (en tu PC) para entrar por SSH sin contraseña |
| **Grupo de seguridad** | Firewall: qué puertos están abiertos y para quién |
| **User data** | Script que se ejecuta automáticamente la primera vez que arranca |
| **Etiquetas** (*tags*) | Nombre y otros datos para organizar las instancias |
| **Estados** | `pending`, `running`, `stopping`, `stopped`, `shutting-down`, `terminated` |

## Antes de empezar

- Terminal configurada ([manual 3](03-configurar-aws-cli.md)).
- Un cliente **SSH**: viene incluido en Windows 10/11, macOS y Linux (comando `ssh`).
- La primera instancia descarga la imagen de Amazon Linux.

## Ejercicio 1: explorar imágenes disponibles

```bash
aws ec2 describe-images --owners amazon --filters "Name=name,Values=*al2023*" --query "Images[].[ImageId,Name]" --output table
```

Usaremos `ami-0c02fb55956c7d316` (Amazon Linux).

## Ejercicio 2: crear la clave SSH

```bash
aws ec2 create-key-pair --key-name clave-clase --query KeyMaterial --output text > clave-clase.pem
```

Protege el archivo (SSH rechaza claves que otros usuarios puedan leer):

**Windows (PowerShell):**

```bash
icacls clave-clase.pem /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

**macOS / Linux:**

```bash
chmod 400 clave-clase.pem
```

> **Guarda bien este archivo.** AWS no vuelve a mostrar la clave privada.

## Ejercicio 3: grupo de seguridad (firewall)

**Windows (PowerShell):**

```bash
$SG = aws ec2 create-security-group --group-name web-sg --description "Web y SSH" --query GroupId --output text
```

**macOS / Linux:**

```bash
SG=$(aws ec2 create-security-group --group-name web-sg --description "Web y SSH" --query GroupId --output text)
```

Abre el puerto 22 (SSH) y el 80 (web):

```bash
aws ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 22 --cidr 0.0.0.0/0
```

```bash
aws ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 80 --cidr 0.0.0.0/0
```

```bash
aws ec2 describe-security-groups --group-ids $SG --query "SecurityGroups[0].IpPermissions[].[FromPort,IpRanges[0].CidrIp]"
```

> `0.0.0.0/0` significa "desde cualquier sitio". En AWS real, para SSH conviene limitarlo a tu IP.

## Ejercicio 4: lanzar una instancia con script de arranque

Crea `arranque.sh`. Se ejecutará solo al arrancar:

```bash
#!/bin/sh
mkdir -p /var/www
echo "<h1>Servidor EC2 de la clase</h1>" > /var/www/index.html
echo "Configurado el $(date)" > /root/bienvenida.txt
```

Lanza la instancia con nombre, clave, firewall y script:

```bash
aws ec2 run-instances --image-id ami-0c02fb55956c7d316 --instance-type t3.micro --key-name clave-clase --security-group-ids $SG --user-data file://arranque.sh --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=servidor-web}]"
```

Comprueba el estado hasta que diga `running`:

```bash
aws ec2 describe-instances --filters "Name=tag:Name,Values=servidor-web" --query "Reservations[].Instances[].[InstanceId,State.Name,PrivateIpAddress]" --output table
```

## Ejercicio 5: entrar por SSH

El SSH de la primera instancia se publica en el puerto **2200** de tu PC (la siguiente en el 2201, etc.). Espera unos 30 segundos tras `running` para que arranque el servicio SSH:

```bash
ssh -i clave-clase.pem -p 2200 root@localhost
```

Acepta la huella con `yes`. Ya estás dentro del servidor:

```bash
cat /etc/os-release
```

```bash
cat /root/bienvenida.txt
```

```bash
ls /var/www
```

`bienvenida.txt` e `index.html` existen: el script de arranque funcionó. Sal con `exit`.

> Si no sabes qué puerto tiene una instancia, búscalo en Docker Desktop: el contenedor `floci-aws-ec2-ID` muestra `2200:22` (o el que le tocó).

## Ejercicio 6: ciclo de vida

Copia el `InstanceId` (empieza por `i-`).

Detener (como apagar el servidor; conserva el disco):

```bash
aws ec2 stop-instances --instance-ids i-XXXXXXXX
```

Arrancar de nuevo:

```bash
aws ec2 start-instances --instance-ids i-XXXXXXXX
```

Añadir más etiquetas:

```bash
aws ec2 create-tags --resources i-XXXXXXXX --tags Key=Curso,Value=bigdata Key=Responsable,Value=ana
```

Buscar por etiqueta:

```bash
aws ec2 describe-instances --filters "Name=tag:Curso,Values=bigdata" --query "Reservations[].Instances[].[InstanceId,State.Name]"
```

Terminar (eliminar para siempre):

```bash
aws ec2 terminate-instances --instance-ids i-XXXXXXXX
```

## Ejercicio 7: redes (VPC)

Toda instancia vive en una **VPC** (red privada virtual) dividida en **subredes**:

```bash
aws ec2 describe-vpcs --query "Vpcs[].[VpcId,CidrBlock,IsDefault]"
```

```bash
aws ec2 describe-subnets --query "Subnets[].[SubnetId,CidrBlock,AvailabilityZone]" --output table
```

Crear tu propia red:

```bash
aws ec2 create-vpc --cidr-block 10.0.0.0/16 --tag-specifications "ResourceType=vpc,Tags=[{Key=Name,Value=red-clase}]"
```

```bash
aws ec2 create-subnet --vpc-id vpc-XXXXXXXX --cidr-block 10.0.1.0/24
```

## Reto

1. Lanza **dos** instancias etiquetadas `Rol=web` y `Rol=base-datos`.
2. Haz que el script de arranque de cada una cree un archivo `/root/rol.txt` con su rol.
3. Entra por SSH a cada una (puertos 2200 y 2201) y comprueba el archivo.
4. Detén solo las instancias con `Rol=web` usando un filtro.
5. Termina todo al acabar.

## Chuleta

| Quiero... | Comando |
|---|---|
| Clave SSH | `aws ec2 create-key-pair --key-name K --query KeyMaterial --output text > K.pem` |
| Firewall | `aws ec2 create-security-group` + `authorize-security-group-ingress` |
| Lanzar | `aws ec2 run-instances --image-id AMI --instance-type t3.micro --key-name K --security-group-ids SG --user-data file://script.sh` |
| Ver | `aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,State.Name]"` |
| Entrar | `ssh -i K.pem -p 2200 root@localhost` |
| Detener / arrancar | `aws ec2 stop-instances` / `start-instances --instance-ids ID` |
| Etiquetar | `aws ec2 create-tags --resources ID --tags Key=K,Value=V` |
| Eliminar | `aws ec2 terminate-instances --instance-ids ID` |
